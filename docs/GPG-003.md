## Scope

- Duplicate removal
- Missing-value treatment (see missingness table in [GPG-002](GPG-002.md#missing-values): `citizen`, `nativity`, `educ99`, `union`)
- Outlier analysis (CPS top-coded `incwage` / `realhrwage` values)
- Categorical encoding  
- Scaling / normalization
- Variable transformation (e.g. `log(realhrwage)`)
- Aggregation or sampling, if necessary

Every preprocessing decision must be justified in this file once work starts.

## Proposed Solution

**Implementation:** [`notebooks/GPG-003_preprocessing.ipynb`](../notebooks/GPG-003_preprocessing.ipynb).
Run it top to bottom after placing `CurrentPopulationSurvey.csv` in `data/` (or set the `CPS_CSV` environment variable).
The notebook records every decision in a log and writes it, with the actual row/column counts of the run, to
[`results/GPG-003_results.md`](results/GPG-003_results.md). Figures are in `docs/figures/GPG-003/`.

**Outputs** (in `data/processed/`, git-ignored): `cps_clean.csv.gz` (cleaned, unscaled — input of GPG-004),
`cps_model_train.csv.gz` / `cps_model_test.csv.gz` (encoded + scaled), `scaler.joblib`, `model_features.json`.

### Decisions and rationale

| # | Topic | Decision | Why |
|---|---|---|---|
| 1 | Loading | `na_values=["NA"]`, lower-cased column names, numeric downcasting; sanity-check that the raw gap reproduces the GPG-002 numbers | GPG-002: missing values are the literal string `NA`. Downcasting keeps the ~280 MB file manageable in memory. |
| 2 | Duplicates | Drop rows identical in **all** columns (keep first) | `serial` is a household id and `wtsupp` a person weight; two real people never match on all ~234 columns, so an exact duplicate is a duplicated record that would be double-counted. |
| 3 | Missing values — `citizen` (87 %) | **Drop the column** | More than half missing, collected in only a few survey years; cannot be imputed credibly. |
| 4 | Missing values — `nativity`, `educ99` (≈25 %), `union` (≈12 %) | **Keep rows.** Verify with a year-by-year heatmap that the missingness is *structural* (question not asked in some years). Fill with an explicit *Unknown* code (`-1` for nominal codes, `0` for the binary `union`) and add an indicator `<col>_missing` | Missing *by design*, not at random: mean/mode imputation would invent values, and dropping rows would delete entire survey years and distort the 1981–2013 trend (RQ1). |
| 5 | Missing values — `hispan` (0.4 %) | Mode imputation | Negligible share, no year pattern. |
| 6 | Education for every row | Derive `edu_group` (Below bachelor's / Bachelor's / Advanced degree) from the complete `ba` / `adv` dummies | `educ99` is missing in early years; education is a key control for RQ2/RQ3, so each row needs it. |
| 7 | Consistency checks | Remove age < 16 or impossible weeks (0–52) / hours (0–99); clip negative `potexp` to 0 and recompute `potexp2`; verify `female` ≡ (`sex` = 2) and `hrwage` ≈ `incwage` / (weeks × hours) | Impossible values are errors; negative experience is meaningless (age − schooling − 6 can fall below 0); `potexp2` must stay consistent with `potexp`. |
| 8 | Non-positive wages | Drop rows with `realhrwage` missing or ≤ 0 | The logarithm is undefined; zero hourly wage is an unpaid/zero-hours artefact, not a wage offer. |
| 9 | Outliers — top-coding | Detect the yearly cap of `incwage` (many rows exactly at the yearly maximum), add flag `top_coded`, **keep the rows** | Top-coding is censoring, not an error. Men are more often at the cap, so deleting these rows would remove mostly high-earning men and *understate* the gender gap. |
| 10 | Outliers — extreme hourly wages | **Winsorize** `ln(realhrwage)` at the 1st / 99th percentile (clip, not delete); keep the unclipped version as `ln_realhrwage_raw` | Hourly wage = annual income / (weeks × hours) explodes for tiny hours; clipping limits leverage on OLS/distance-based models without losing any worker (needed for subgroup and trend analysis). 3×IQR fences are reported as a diagnostic. |
| 11 | Transformation | Target `ln_realhrwage` = log of the real hourly wage (also `ln_incwage`) | Wages are strongly right-skewed (skewness reported in the notebook); log makes the distribution near-symmetric and lets coefficients be read as ≈ % differences (Mincer equation, GPG-002). |
| 12 | Aggregation / sampling | No row sampling for modelling; save weighted year × sex summary to `docs/results/agg_year_sex.csv` | The full data fits in memory and subsampling would only reduce precision. The aggregate supports the time-trend question (RQ1) and respects the survey weight `wtsupp`. Only slow plots/tests in GPG-004 use a random subsample. |
| 13 | Features removed from the model matrix | `incwage`, `hrwage`, `realhrwage`, `lnrwg`, `incbus`, `incfarm`, `top_coded` (target leakage); `serial`, `wtsupp` (ID / weight, kept as `sample_weight`); `sex` (≡ `female`); constants (`empstat`, `labforce`); `occ1990`, `ind1990`, `statefip` (hundreds of nominal codes — occupation/industry/region dummies cover them; target/frequency encoding is GPG-005) | Prevents leakage, redundancy and zero-variance columns. |
| 14 | Categorical encoding | One-hot (`drop_first=True`) for nominal codes `race`, `marst`, `hispan`, `nativity`, `classwkr`, `educ99`, `adj_occ2name`; existing 0/1 dummies kept; `edu_group` and `region` not one-hot encoded when `ba`/`adv` and region dummies already exist | Numeric codes (e.g. race = 651) are labels with no order — one-hot avoids a false ordering; `drop_first` avoids the dummy-variable trap. |
| 15 | Collinearity | Gram–Schmidt check on a 30k sample (with intercept); drop linearly dependent dummy columns | Exhaustive dummy sets and duplicated missing-indicators are exact linear combinations and make OLS ill-defined. |
| 16 | Scaling | `StandardScaler` on `age`, `potexp`, `potexp2`, `wkswork1`, `uhrswork`, `year`; dummies not scaled; **fitted on the 80 % training split only** | Needed for regularized/distance-based/NN models, harmless for trees. Fitting on train only avoids test-set leakage. |
| 17 | Train/test split | 80/20, stratified by `female`, `random_state=42` | Keeps the sex ratio equal in both parts; fixed seed for reproducibility. |
| 18 | Validation | Asserts: no NaN/inf, all columns numeric, no wage-derived column among the features | Guarantees a model-ready, leakage-free matrix. |

### Known limitations

- Winsorization bounds are computed on the full cleaned sample (descriptive clipping); the scaler — which matters for leakage — is fitted on train only.
- The `-1` Unknown level and the `*_missing` indicators encode *which survey years asked the question*; they should be interpreted as "not asked", not as a real category.
