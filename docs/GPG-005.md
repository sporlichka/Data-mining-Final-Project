## Proposed Solution

**Implementation:** [`notebooks/GPG-005_feature_engineering.ipynb`](../notebooks/GPG-005_feature_engineering.ipynb) — run
[`GPG-003_preprocessing.ipynb`](../notebooks/GPG-003_preprocessing.ipynb) first (it creates `data/processed/cps_model_train.csv.gz`
/ `cps_model_test.csv.gz` / `model_features.json`, already cleaned, encoded and scaled). The notebook writes its numbers to
[`results/GPG-005_findings.md`](results/GPG-005_findings.md) and figures to `docs/figures/GPG-005/`.

`potexp2` (experience²) already exists from [GPG-003](GPG-003.md) decision #7, so the scope's two new features are the other
two examples it names: an **occupation-level gender segregation index** and an **education × occupation interaction**.

### New features

| # | Feature | Definition | Why |
|---|---|---|---|
| 1 | `occ_pct_female` | Share of women in the worker's occupation group, fit on the **train split only** and mapped onto train/test (no leakage). `occ_group` collapses the 21 occupation dummy flags (`manager`, …, `production`) plus the implicit 22nd baseline category (all-zero rows) into one categorical. | Turns the GPG-004 descriptive segregation chart into a row-level predictor; occupational sex segregation is a standard channel for the "unexplained" gap (RQ2/RQ3). |
| 2 | `edu_occ_interaction` | `edu_level` (0 = below bachelor's, 1 = bachelor's, 2 = advanced, from `ba`/`adv`) × `occ_skill_tier` (1–3, occupations grouped into production/service, technical/sales/admin, professional/managerial). Range 0–6. | The wage return to a degree differs by occupation (steeper for managers/lawyers/physicians than production work); a single `female`/education-only model can't capture that interaction. |

**Note on the implicit baseline category.** The 21 occupation dummies used in the model matrix have no "missing/other"
bucket — their all-zero baseline was checked row-by-row against `adj_occ2name` and found to match **exactly**
("Transportation and materials moving", 21,277 rows in both, 100% overlap). This is a *different* variable from
`adj_occ2name`'s own `"."` / `"Other"` category (132,708 rows, relabelled `"Other"` in the GPG-004 notebook): checked the
same way, that `"."` group has **zero overlap** with the Transportation baseline — the occupation dummies that actually
fire inside it are `sales`, `legaleduc`, `foodcare`, `healthcare`, `building`, `architect`, `healthsupport`, `artist`,
`scientist`, `postseceduc`, matching GPG-004's own description ("missing... for sales, education, healthcare,
food-service and other jobs"). So GPG-004's finding stands unchanged; the 21-dummy encoding used here simply has no
missing-occupation problem to begin with, which is why it was used as the basis for `occ_group` instead of rebuilding
anything from `occ1990`.

Range/validity actually observed on the run: `occ_pct_female` spans 0.031–0.904 (overall female share 0.489);
correlation with `female` is 0.519 and with the target 0.412/−0.128 respectively for the two new features (see
`results/GPG-005_findings.md` for the exact numbers from the current run).

### Feature selection

| Step | Method | Finding |
|---|---|---|
| Collinearity | VIF on a 30k sample over `occ_pct_female` + the 21 occupation dummies + controls | `occ_pct_female` and the occupation dummies that drive it show astronomically high VIF (~10¹⁵) — expected, since `occ_pct_female` is by construction an exact linear combination of the occupation-dummy block. It is a **linear-model redundancy**, not a data error. |
| Ranking | `LassoCV` (5-fold, standardized) and `RandomForestRegressor` (80k-row subsample) over the 96 base + 2 new features | 10/98 features have a near-zero Lasso coefficient; **none** are near-zero in *both* Lasso and RF, so nothing is dropped on signal grounds. Both new features rank highly in the RF importance (`edu_occ_interaction` #1, `occ_pct_female` #3 of 98) — the non-linear model exploits the segregation index despite its linear collinearity. |
| Decision | Keep both new features in the saved matrix | Collinearity only matters for a strictly linear fit; GPG-007's tree/boosting models are unaffected, and `occ_pct_female` is still useful there. For a linear baseline (GPG-006), `occ_pct_female` is redundant *given* the occupation dummies and can simply be left out of a linear specification if its coefficient misbehaves — no row needs to be dropped either way. |

### PCA on the occupation/industry dummy block

PCA was run on the 36-column occupation (21) + industry (15) binary-dummy block (train-fitted `StandardScaler` + `PCA`), and
three encodings were compared via 5-fold CV `R²` on `ln_realhrwage` with a plain linear model, holding every other feature fixed:

| Encoding | # columns (occ/ind block) | CV R² |
|---|---|---|
| A — raw dummies (GPG-003 baseline) | 36 | **0.4291** ± 0.0026 |
| B — PCA (k components, ≥ 90% variance) | 27 | 0.4269 ± 0.0026 |
| C — compact encoding (`occ_pct_female` + `occ_skill_tier`, industry dummies kept raw) | 17 | 0.4158 ± 0.0023 |

**Decision: keep the raw dummies (A), do not adopt PCA for modelling.** The 36-column block needs 27 components to reach
90% of its variance — it is not actually very compressible (the occupation/industry categories are close to mutually
exclusive, so they are already close to orthogonal) — so PCA only trims 9 columns while *losing* interpretability and a
small amount of `R²`. The compact hand-built encoding (C) is more interpretable but costs ~1.3 points of `R²`, so it is not
used as the default either; it stays available (`occ_pct_female`, `occ_skill_tier`) as optional lower-dimensional features
for models that need them (e.g. a quick interpretable linear baseline).

### Outputs

`data/processed/cps_model_train_fe.csv.gz` / `cps_model_test_fe.csv.gz` (98 features: the 96 from GPG-003 + the 2 new
ones; same `sample_weight`/target columns), `model_features_fe.json` (feature list + which encoding/drops were applied),
`gpg005_transformers.joblib` (the occupation female-share mapping, skill-tier dict, dummy-block scaler and fitted PCA, for
reuse at inference time). GPG-006+ should load `cps_model_train_fe.csv.gz` / `model_features_fe.json` going forward.

### Known limitations

- `occ_pct_female` is fit on the train split only, but it is still a **target-adjacent** feature at the aggregate level
  (it uses `female`, not the wage target, so it does not leak the regression target — but it does mean a model with this
  feature is partly "told" the occupation's sex composition instead of discovering it).
- The 3-tier occupation skill classification (`SKILL_TIER` in the notebook) is a simplification designed for the
  interaction term, not a validated external skill index; GPG-009 should describe it as such if cited in the report.
